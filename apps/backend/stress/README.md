# Нагрузочный тест API

Скрипты без внешних зависимостей (Node 22). Запускайте **только на копии базы**: подготовка
создаёт тестовые учётные записи `*@stress.local` и может опубликовать черновики расписания.

## 1. Подготовка

```bash
cd apps/backend
STRESS_CONFIRM=yes node stress/prepare-users.js --students 1000 --teachers 25 --admins 3 --publish
```

- студенты распределяются по группам, у которых есть занятия;
- преподаватели — те, у кого больше всего занятий (и ещё нет учётной записи);
- пароль у всех `Stress123!` (меняется переменной `STRESS_PASSWORD`);
- `--publish` публикует черновики, иначе студенты не видят занятий;
- `--cleanup` удаляет все тестовые учётные записи.

## 2. Запуск

```bash
node dist/main.js & echo $! > /tmp/api.pid        # API в отдельном процессе

BACKEND_PID=$(cat /tmp/api.pid) \
PG_URL=postgresql://postgres:postgres@localhost:5432/schedule \
DURATION=300 RAMP=60 THINK=3-10 \
node stress/run.mjs --out stress-results/realistic.json
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `STUDENTS`, `TEACHERS`, `ADMINS` | 1000, 25, 3 | число виртуальных пользователей |
| `RAMP` | 60 | за сколько секунд все входят; `0` — все сразу («утро понедельника») |
| `DURATION` | 300 | сколько секунд длится нагрузка после входа |
| `THINK` | `3-10` | пауза студента/преподавателя между действиями, с; `0-1` — почти без пауз |
| `ADMIN_THINK` | `2-6` | пауза администратора, с |
| `GENERATE_EVERY` | 120 | каждый администратор запускает генерацию раз в N секунд (`0` — нет) |
| `STEADY_AFTER` | `RAMP+15` | с какой секунды считать «установившийся режим» |
| `BACKEND_PID` | — | замер CPU и памяти процесса API (в т. ч. основного потока Node) |
| `PG_URL` | — | активные соединения Postgres и топ запросов (`pg_stat_statements`) |

Что делает каждая роль:

- **студент** — главная (профиль, уведомления, дашборд, периоды) или «Моё расписание»
  на эту/следующую неделю; 2% — скачивание PDF;
- **преподаватель** — главная, своё расписание с доступностью, своя нагрузка, 5% — PDF;
- **администратор** — неделя группы с конфликтами и событиями графика, правка занятия
  (открыть → проверить слот → сохранить), проверка расписания, «Нагрузка преподавателей»,
  «Выполнение часов», отчёт, Excel и раз в `GENERATE_EVERY` секунд — генерация (без применения).

Итог: таблицы p50/p95/p99/max по каждому запросу и по «страницам» (все запросы страницы
параллельно, как в браузере) — за весь тест и за установившийся режим, доля ответов из кэша
Redis (`cacheHitPct`), ошибки по причинам, RPS по секундам, CPU/память API и Postgres,
задержка `/health` (признак занятости основного потока).

Генератор нагрузки и API на одной машине делят процессор — для чистых замеров
запускайте `run.mjs` с другой машины (`BASE_URL=http://сервер:3000/api`).
