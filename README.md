# Расписание СПО и ВО — автоматизированное составление расписания колледжа и вуза

Веб-приложение для колледжей, вузов и филиалов, где в одной организации учатся студенты СПО и высшего образования
(бакалавриат, специалитет, магистратура): хранение учебных планов, расчёт пар по часам, автоматическое составление
расписания сразу для всех групп на неделю, месяц, семестр или учебный год, контроль выполнения часов, учёт
проведённых, отменённых и перенесённых занятий, замены преподавателей и отработки.

## Возможности

| Блок | Что умеет система |
| --- | --- |
| Мастер настройки | Пошаговое сопровождение администратора от настроек организации до публикации расписания: что сделано, что осталось, подсказка «Шаг N из 10» на каждой странице; после завершения всех шагов пропадает из меню и открывается из «Настроек» |
| СПО и ВО в одной организации | Уровень образования специальности (направления) определяется по коду: 00.02.00 — СПО, 00.03.00 — бакалавриат, 00.04.00 — магистратура, 00.05.00 — специалитет; фильтры и отчёты по уровням; очная, очно-заочная и заочная формы; до 7 курсов и 14 семестров |
| Импорт плана со скана | Загрузите учебный план (скан, фото или PDF из программ планирования) — система распознает титульный лист, календарный учебный график и план по семестрам или сессиям (заочная форма), проверит суммы часов, покажет сомнительные места с фрагментами скана и после подтверждения сама создаст специальность, план, учебные годы, семестры, циклы, дисциплины (ПМ, МДК, практики, модули ВО, дисциплины по выбору и факультативы) с часами и формами контроля, календарный график и группу. У цифровых PDF текст берётся из текстового слоя — без ошибок распознавания и за секунды |
| Учебные планы | Специальности СПО и направления подготовки ВО, образовательные программы, циклы и блоки (Б1, Б2, Б3, ФТД), дисциплины, ПМ, МДК, практики; часы по видам занятий и семестрам; формы контроля; дисциплины по выбору ставятся в расписание только выбравшим группам; импорт из Excel по шаблону |
| Расчёт пар | 1 пара = 2 академических часа; нечётные часы дают неполную пару (1 ч), она отмечается в расписании и в предупреждениях |
| Календарный график | Недели теоретического обучения, аттестации, практик и каникул; праздники; отпуска преподавателей; прогноз ёмкости семестра |
| Нагрузка | Назначение преподавателей на дисциплины и виды занятий, подгруппы (лабораторные, иностранный язык), недельная интенсивность; вкладка «Потоки» — один преподаватель ведёт пару сразу у нескольких групп (физкультура, общие лекции), генератор ставит её одновременно, при переносе пара потока переезжает целиком |
| Режим занятий группы | Учебные дни и допустимые пары группы: вторая смена, вечерние и очно-заочные группы; генератор и проверка расписания его учитывают |
| Преподаватели | Плитки с фото, должностью (ассистент, преподаватель, старший преподаватель, доцент, профессор…), учёной степенью и званием, образованием и уровнями, у которых преподаватель может вести занятия: бакалавр — только СПО, магистр — СПО и бакалавриат, специалист — также специалитет, высшая квалификация — также магистратура, кандидат или доктор наук, доцент или профессор — все уровни (можно задать вручную). Ограничение соблюдают нагрузка, генератор, проверка расписания и замены. Карточка: дисциплины по группам, расписание, ограничения (когда, во сколько, на какой неделе, онлайн, отпуска), нагрузка |
| Смена преподавателя в семестре | Период работы («работает с 01.11», «по 31.12»): до и после него занятия не ставятся. «Передать нагрузку с даты»: будущие занятия переходят к новому преподавателю, прошедшие остаются за прежним, плановые часы делятся между ними; составление расписания с даты распределяет оставшиеся часы по оставшимся неделям |
| Доступность преподавателей | Недельная сетка со временем пар и гибкие правила: «не может», «может только», «желательно», «нежелательно», «онлайн»; дни недели, номера пар или интервал времени, чётные/нечётные недели, недели месяца («первая неделя месяца», «последняя суббота месяца»), период действия; преподаватель может указать свою доступность сам. Сетка заполняется «кистью»: справа выбирается режим, затем ячейки закрашиваются нажатием или протягиванием, нажатие на день или пару — целиком. Отпуск, больничный, курсы с тумблером «Отработать пропущенные пары после выхода»: уже поставленные пары переносятся на ближайшее время после выхода, генератор ставит их туда же сверх недельного лимита |
| Автосоставление | Кнопка «Составить расписание для всех групп»: для каждой группы берётся текущий семестр, недостающие периоды создаются автоматически, расписание всех групп СПО и ВО составляется одной задачей — общие преподаватели и аудитории без накладок. Календарный режим (по датам, рекомендуется) и шаблон недели; OR-Tools CP-SAT и эвристика — берётся лучший результат, затем доводка окон перестановками внутри дня и недели; ровная нагрузка преподавателя по неделям; при составлении на неделю или месяц ставится только доля оставшихся часов, остальное распределяется по следующим неделям; жёсткие и мягкие ограничения; частичный результат с причинами и рекомендациями по неразмещённым занятиям |
| Ручная правка | Перетаскивание занятий с мгновенной проверкой конфликтов (на странице расписания и в карточках группы, преподавателя, аудитории), добавление, копирование, массовое редактирование, закрепление |
| Проверка | Блокирующие ошибки (пересечения групп, преподавателей, аудиторий, вместимость, тип аудитории, доступность) и предупреждения (окна, перегрузка, поздние пары, дефицит часов); публикация невозможна при ошибках |
| Устранение конфликтов | Для каждой ошибки — готовые варианты исправления, проверенные на отсутствие новых конфликтов: перенос в свободный слот, другая аудитория, замена преподавателя, удаление дубликата или лишних занятий; применение в один клик и «Исправить всё автоматически» |
| Контроль часов | План / в расписании / проведено / осталось / дефицит / превышение по видам занятий; прогноз к концу семестра; разрезы по группам, дисциплинам, преподавателям, семестрам, программам, уровням образования и организации в целом |
| Факт проведения | Проведено, частично проведено, отменено (с причиной), перенесено, замена; отмена создаёт задачу «требуется отработка» и предлагает свободные слоты; перенос сохраняет связь с исходным занятием без двойного учёта часов; автозачёт — закончившаяся пара опубликованного расписания без отметок засчитывается проведённой (настройка «Засчитывать проведённые пары автоматически») |
| Отчёты и экспорт | 12 отчётов (расписания, нагрузка, выполнение плана, дефицит часов, отмены, переносы, замены, практика, аттестация, загрузка аудиторий) в Excel и PDF; PDF-сетки расписаний; печатная форма на неделю по специальности (как утверждаемый бумажный бланк: грифы «Согласовано» и «Утверждаю», курсы и группы столбцами, дни и пары строками, аудитории, подпись) в PDF и Excel |
| Роли | Администратор, диспетчер (методист), преподаватель, студент, руководитель — с разграничением доступа на уровне API |

Не ставятся в сетку автоматически: самостоятельная работа, часы экзаменов и зачётов, защита курсовых, ГИА, выездная
производственная и преддипломная практика — они отражаются в календарном графике. В расписание попадают лекции,
практические и лабораторные занятия, консультации (если включены) и практика, проводимая на базе организации. У заочной
формы занятия ставятся только в даты сессий из «Графика сессий» учебного плана.

## Архитектура

```
┌────────────────┐   /api    ┌──────────────────────────────────────────┐
│  frontend      │ ────────▶ │  backend (NestJS)                        │
│  React + nginx │           │  REST, Swagger, JWT, BullMQ worker       │
└────────────────┘           │  └─ python -m app (подпроцесс):          │
                             │     решатель OR-Tools CP-SAT,            │
                             │     распознавание сканов (OpenCV,        │
                             │     Tesseract OCR)                       │
                             └──────────┬───────────────┬───────────────┘
                                        │               │
                                   PostgreSQL     Redis (очередь генерации)
```

Приложение собирается в **два Docker-образа**: `backend` (API вместе с Python-модулем решателя и распознавания) и
`frontend` (nginx). PostgreSQL и Redis — стандартные образы.

- `apps/backend` — NestJS 11, Prisma 6, PostgreSQL, BullMQ, JWT, Swagger, экспорт Excel (exceljs) и PDF (pdfmake).
- `apps/frontend` — React 19, TypeScript, Vite, Tailwind CSS 4, компоненты в стиле shadcn/ui (Radix), TanStack Query и
  Table, React Hook Form + Zod, FullCalendar, Recharts, DnD Kit.
- `apps/solver` — Python 3.11: Google OR-Tools CP-SAT (понедельная модель с жёсткими и мягкими ограничениями) и
  распознавание сканов учебных планов (pypdfium2, OpenCV, Tesseract). Запускается API как подпроцесс
  `python -m app <команда>`; отдельный сервис не нужен.
- `docs/` — проектная документация: архитектура, схема БД, расчёт часов, алгоритм, разрешение конфликтов, API,
  интерфейс, план реализации.

Если Python-модуль недоступен, API автоматически использует встроенный эвристический генератор (`SOLVER_MODE=auto`);
если не задан Redis, генерация выполняется в процессе API.

### С чего начать

Войдите администратором и откройте **«Мастер настройки»** (первый пункт меню, после завершения — кнопка в «Настройках»): он ведёт по шагам — настройки

странице или на странице «Автосоставление» → «Все группы»: перед запуском видно, какие группы и семестры войдут в
расписание и какие периоды будут созданы.

## Локальная разработка

Требования: Node.js 22, npm 10, PostgreSQL 16; по желанию Redis 7, Python 3.11 (решатель CP-SAT и распознавание
сканов) и Tesseract OCR с русским языком (`apt install tesseract-ocr tesseract-ocr-rus`).

```bash
npm ci
cp apps/backend/.env.example apps/backend/.env         # строка подключения к PostgreSQL, секреты JWT
npm run prisma:deploy -w apps/backend                   # миграции
npm run seed -w apps/backend                            # демо-данные (повторно: npm run seed -w apps/backend -- --reset)
npm run dev:backend                                     # API: http://localhost:3000/api, Swagger: /api/docs
npm run dev:frontend                                    # интерфейс: http://localhost:5173 (проксирует /api)
```

Python-модуль (решатель и распознавание):

```bash
cd apps/solver
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt                     # API найдёт apps/solver/.venv автоматически
python -m app info                                      # версии OR-Tools и Tesseract
```

Основные переменные окружения API (`apps/backend/.env.example`):

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | Секреты токенов доступа и обновления |
| `JWT_ACCESS_TTL`, `JWT_REFRESH_TTL` | Срок жизни токенов (по умолчанию 15m и 7d) |
| `REDIS_URL` | Redis для очереди генерации BullMQ; пусто — генерация в процессе API |
| `SOLVER_MODE` | Решатель: `auto` (эвристика как стартовое решение для CP-SAT, в итог — лучший из двух вариантов; без CP-SAT — эвристика), `cp-sat`, `heuristic` |
| `SOLVER_ROOM_VARIABLES_LIMIT` | Порог размера недельной модели CP-SAT, выше которого аудитории назначаются после решения (по умолчанию 60000) |
| `PYTHON_BIN`, `ENGINE_DIR` | Интерпретатор Python и каталог модуля `apps/solver` (по умолчанию определяются автоматически) |
| `CORS_ORIGIN` | Разрешённые источники запросов (через запятую) |

## Тесты и проверки

```bash
npm run lint && npm run typecheck                      # ESLint и TypeScript для backend и frontend
npm test -w apps/backend                               # модульные тесты: часы, даты, темп, календарь, генератор
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/schedule_test \
  npm run test:e2e -w apps/backend                     # e2e: генерация, публикация, конфликты, отмены, отработки, роли
npm test -w apps/frontend                              # тесты интерфейса (Vitest)
cd apps/solver && pytest -q && ruff check .            # тесты решателя и распознавания, линтер
```

E2E-тесты пересоздают данные, поэтому имя тестовой базы должно содержать `test`.

## CI/CD и автоматический релиз

- **CI** (`.github/workflows/ci.yml`) — на каждый push в рабочие ветки и pull request: ESLint, Prettier, проверка типов,
  модульные и e2e-тесты backend с PostgreSQL и Redis, контроль соответствия миграций схеме Prisma, линтер и сборка
  frontend, Ruff и pytest Python-модуля (с Tesseract), сборка двух Docker-образов.
- **Release** (`.github/workflows/release.yml`) — на каждый push в `main` (или `master`): те же проверки, затем
  [semantic-release](https://semantic-release.gitbook.io/) по сообщениям коммитов определяет версию
  (`fix` → patch, `feat` → minor, `BREAKING CHANGE` → major), обновляет `CHANGELOG.md` и версии пакетов, создаёт тег
  `vX.Y.Z` и GitHub Release, после чего публикует образы `backend` и `frontend` в `ghcr.io` с тегами
  `X.Y.Z`, `X.Y`, `X` и `latest`.
- Сообщения коммитов — в формате [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat(schedule): …`,
  `fix(hours): …`, `docs: …`. Коммиты без `feat`/`fix`/`perf`/`refactor` релиз не создают.

Для публикации релизов достаточно стандартного `GITHUB_TOKEN`; в настройках репозитория (Settings → Actions → General)
должно быть разрешено «Read and write permissions» для workflow.

Первый релиз: создайте ветку `main` из текущей рабочей ветки (или влейте её в `main` через pull request) — workflow
«Release» выпустит версию `1.0.0` и опубликует образы. Ручной запуск «Release» (Actions → Release → Run workflow) на
другой ветке выполняет только проверки: semantic-release работает лишь в `main`/`master`.
