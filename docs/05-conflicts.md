# 5. Стратегия разрешения конфликтов

Конфликты предотвращаются на трёх уровнях: при генерации (ограничения модели), при ручной правке (мгновенная
проверка занятия) и перед публикацией (полная проверка периода). Код: `apps/backend/src/validation`.

## Классификация

### Блокирующие ошибки (публикация невозможна)

| Код | Проверка |
| --- | --- |
| `GROUP_CONFLICT` | Группа (или пересекающаяся подгруппа) на двух занятиях одновременно; занятие всей группы конфликтует с подгрупповым |
| `TEACHER_CONFLICT` | Преподаватель на двух занятиях одновременно (кроме общего потока групп) |
| `CLASSROOM_CONFLICT` | Аудитория занята дважды (кроме общего потока) |
| `CAPACITY_EXCEEDED` | Вместимость аудитории меньше численности группы или подгруппы |
| `WRONG_CLASSROOM_TYPE` | Тип аудитории не соответствует требованиям дисциплины (например, лабораторная не в лаборатории) |
| `TEACHER_UNAVAILABLE`, `CLASSROOM_UNAVAILABLE` | Недоступное время преподавателя или аудитории (сетка доступности, отпуск, командировка) |
| `LESSON_IN_VACATION`, `LESSON_IN_PRACTICE`, `LESSON_ON_HOLIDAY`, `LESSON_IN_BLOCKED_PERIOD` | Обычное занятие в каникулы, в период практики на предприятии, в праздник или в заблокированный графиком период |
| `LESSON_OUTSIDE_SEMESTER`, `LESSON_OUTSIDE_PERIOD` | Занятие вне дат семестра или периода расписания |
| `NO_TEACHER`, `NO_CLASSROOM` | Занятие без преподавателя или аудитории |
| `HOURS_EXCEEDED` | Часов в расписании больше, чем по плану, без разрешения превышения |

### Предупреждения (публикация разрешена)

| Код | Проверка |
| --- | --- |
| `HOURS_DEFICIT` | В расписании меньше часов, чем по плану |
| `HOURS_EXCESS_APPROVED` | Превышение часов, разрешённое назначением или занятием |
| `PARTIAL_LESSON` | Неполная пара (нечётное число часов) |
| `GROUP_DAILY_LIMIT` | У группы больше пар в день, чем допустимо |
| `TEACHER_OVERLOAD` | Превышение недельной или дневной нагрузки преподавателя |
| `GROUP_WINDOWS`, `TEACHER_WINDOWS` | Окна сверх допустимого числа в неделю |
| `LATE_LESSONS` | Поздние пары |
| `UNEVEN_DISTRIBUTION` | Дисциплина распределена неравномерно (перекос по неделям) |
| `NOT_ENOUGH_WEEKS` | Учебных недель не хватает для закрытия часов |
| `TOO_MANY_EXAMS` | Много экзаменов у группы в одну неделю |
| `LESSON_ON_DAY_OFF`, `LESSON_NUMBER_EXCEEDS` | Занятие в выходной день или пара вне сетки звонков |
| `UNASSIGNED_TEACHER` | Дисциплина без назначенного преподавателя |

Результаты проверки сохраняются (`ValidationResult`), выводятся на странице расписания и на главной; публикация
запрещена, пока есть ошибки.

## Генерация

- Жёсткие ограничения заложены в модель (CP-SAT) или проверяются перед постановкой (эвристика) — генератор не
  создаёт конфликтов.
- Если разместить всё невозможно, генератор не ослабляет жёсткие ограничения, а возвращает **частичный результат**:
  список неразмещённых занятий с причинами и рекомендациями (см. [алгоритм](04-algorithm.md#результат-и-диагностика)).
- При применении результата ручные, закреплённые и проведённые занятия сохраняются; если слот успели занять
  вручную после генерации, конфликтующее занятие пропускается и указывается в отчёте применения.

## Ручная правка

1. При перетаскивании, создании, изменении, копировании и замене сервер выполняет проверку занятия
   (`POST /schedule-lessons/check` — та же проверка без сохранения).
2. При блокирующих конфликтах возвращается `409` со списком конфликтов; интерфейс показывает их и предлагает
   отменить действие или выполнить его «несмотря на конфликты» (только администратор и диспетчер, `force: true`).
3. Принудительно сохранённый конфликт попадает в полную проверку периода и не даст опубликовать расписание, пока его
   не устранят.
4. Для переноса и отработки система подбирает **свободные слоты**: даты и пары, где свободны группа (подгруппа),
   преподаватель и подходящая аудитория, с учётом календарного графика и доступности; слоты ранжируются по близости
   к исходной дате, отсутствию окон и перегрузки дня группы, поздним парам и пожеланиям преподавателя.

## Отмены, переносы и замены

| Ситуация | Обработка |
| --- | --- |
| Отмена | Статус «отменено», причина (отсутствие группы или преподавателя, аудитория недоступна, праздник, иное). Часы не засчитываются; создаётся задача «требуется отработка»; сразу предлагаются свободные слоты |
| Перенос | В опубликованном расписании и для прошедших дат исходное занятие получает статус «перенесено», создаётся новое со ссылкой на исходное; в черновике возможно изменение на месте. Двойного учёта часов нет |
| Замена преподавателя | Проверка занятости и доступности заменяющего; запись `TeacherSubstitution`; факт засчитывается заменяющему |
| Частичное проведение | Отметка с фактическими часами меньше плановых; недостающие часы видны как дефицит прогноза |
| Неотмеченные прошедшие занятия | Показываются преподавателю на главной и учитываются в статусе «риск» |

Все изменения записываются в журнал аудита, а участникам (группе, преподавателям) отправляются уведомления.
