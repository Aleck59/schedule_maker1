# 4. Алгоритм генерации расписания

Код: `apps/backend/src/scheduler` (построение задачи, эвристика, диагностика, задания) и `apps/solver/app` (CP-SAT,
запускается из API подпроцессом `python -m app solve`: задача — JSON в stdin, результат — JSON в stdout).
Контракт задачи и результата общий для обоих решателей (JSON, `solver.types.ts` ↔ `models.py`).

## Режимы

| Режим | Когда использовать | Как работает |
| --- | --- | --- |
| Календарный (по датам) — рекомендуется | Семестр с праздниками, практиками, сессией, неравномерными неделями | Каждое занятие ставится на конкретную дату; учитываются все блокировки графика |
| Постоянная неделя | Стабильное расписание «по неделям» | Строится шаблон недели (пар в неделю ≈ часы / число учебных недель), затем разворачивается по датам с пропуском заблокированных дней; остаток часов добирается компенсационным проходом |

Практика на базе организации и консультации всегда ставятся по датам (в периоды практики и перед окончанием семестра).

## Расписание для всех групп

Кнопка «Составить расписание для всех групп» (`POST /api/generation/all`) готовит одну совместную задачу:

1. Для каждой активной группы (с фильтром по уровню образования или учебным планам) берётся семестр её учебного
   плана, идущий на выбранную дату; на каникулах перед семестром — ближайший семестр, если он начинается в течение
   45 дней. Группы без семестра на дату (обучение завершено, между семестрами) пропускаются с объяснением.
2. Для каждого такого семестра используется существующий период расписания или создаётся новый на даты семестра.
3. Строится одна задача на все периоды: у каждой группы свой интервал (даты её периода и семестра), а преподаватели,
   аудитории и уже поставленные занятия общие. Поэтому занятия разных учебных планов (СПО и ВО, очная и
   очно-заочная формы) не пересекаются по преподавателям и аудиториям.
4. Результат применяется ко всем периодам сразу: каждое занятие попадает в период своей группы.

## Режим занятий группы и дисциплины по выбору

- **Режим занятий** группы — учебные дни (`studyDays`) и допустимые пары (`firstLessonNumber`–`lastLessonNumber`):
  вторая смена, вечерние и очно-заочные группы. Даты вне учебных дней не входят в доступные даты группы, пары вне
  диапазона не рассматриваются решателем (`allowedLessons` в задаче); при ручной правке — предупреждение.
- **Дисциплины по выбору и факультативы** (`isRequired = false`: вторая и следующие дисциплины блока ДВ, ФТД)
  ставятся в расписание только группам, которым назначена нагрузка по ним.
- **Заочная форма**: при импорте плана часы сессий сводятся в семестры (установочная и зимняя — нечётный, летняя —
  чётный), а дни вне сессий из «Графика сессий» становятся блокирующим периодом «Межсессионный период», поэтому
  занятия заочников ставятся только в даты сессий.

## Подготовка задачи

1. **Горизонт**: даты периода (или выбранный интервал) ∩ даты семестра, только рабочие дни недели.
2. **Календарь группы** (`CalendarContext`): для каждой даты — разрешены ли обычные занятия, идёт ли практика,
   какие события блокируют (каникулы, сессия, праздники, ГИА, практики на предприятии).
3. **Спрос**: потоки часов (см. [расчёт часов](03-hours.md)) → требуемое число пар с учётом уже существующих
   занятий: закреплённых, ручных, проведённых и находящихся вне интервала генерации. Неполная пара — отдельное
   требование с `academicHours = 1`.
4. **Допустимые аудитории** для каждого потока: тип аудитории (из плана или назначения), вместимость ≥ размер группы
   или подгруппы, доступность; предпочтительная аудитория получает бонус.
5. **Преподаватели**: недоступные слоты недельной сетки (жёстко), предпочтения (веса), лимиты пар в день и неделю,
   периоды отсутствия из графика, даты вне периода работы (`employedFrom`/`employedTo` — вышел в середине семестра,
   уволился). Поток, преподаватель которого по образованию не может вести занятия этого уровня (бакалавр — только СПО,
   магистр — СПО и бакалавриат…), или который не работает ни дня в интервале, сразу попадает в непоставленные с
   причиной `TEACHER_LEVEL` или `TEACHER_NOT_EMPLOYED`. Гибкие правила доступности вычисляются на каждую дату и пару горизонта и передаются
   решателю как `blockedSlots` (запрет, «только в указанное время»), `slotPreferences` (желательно / нежелательно) и
   `onlineSlots` (онлайн): в онлайн-слоте занятие ставится в онлайн-аудиторию (`onlineRoomId`), а не в обычную.
6. **Фиксированные занятия** занимают слоты групп, преподавателей и аудиторий и не изменяются.

## Темп распределения

Чтобы часы шли равномерно, а не «в начале семестра», для каждого потока считается накопительная цель к концу
недели:

```
цель(w) = min(требуется, round(max(требуется × дней_до_конца_w / всего_дней,  интенсивность × недель_до_w)))
```

где «дни» — учебные дни группы, а интенсивность — `weeklyLessonTarget` назначения (если задана). В неделю ставится
`цель(w) − уже поставлено`; отставание компенсируется в следующих неделях.

## OR-Tools CP-SAT (основной решатель)

Модель строится по неделям (скользящий горизонт): булевы переменные `x[поток, день, пара, аудитория]` только для
допустимых сочетаний.

Жёсткие ограничения:

- группа (вся или подгруппа) — не более одного занятия в слоте; занятие всей группы исключает подгрупповые в этом слоте;
- преподаватель — не более одного занятия в слоте (общий поток групп — одно занятие);
- аудитория — не более одного занятия в слоте, тип и вместимость подходят;
- доступность преподавателя (сетка и гибкие правила по датам) и аудитории, календарные блокировки (разрешённые даты);
- в онлайн-слотах преподавателя — только онлайн-аудитория;
- лимиты преподавателя в день и неделю, не более N пар одной дисциплины в день, сетка звонков (пар в день);
- число поставленных пар потока за неделю не превышает недельной потребности.

Мягкие ограничения (штрафы, веса настраиваются в «Настройках»):

| Штраф | Вес по умолчанию |
| --- | --- |
| Окна у групп | 30 |
| Превышение комфортного числа пар группы в день | 25 |
| Переходы между корпусами | 15 |
| Окна у преподавателей | 10 |
| Неравномерность по неделям | 10 |
| Поздние пары | 8 |
| Нарушение пожеланий преподавателя | 6 |
| Сложные дисциплины в конце дня | 6 |
| Превышение частоты дисциплины в неделю | 5 |
| Повтор дисциплины в один день | 3 |

Цель: максимум поставленных пар (с учётом приоритета потока) минус штрафы. Лимит времени делится между неделями.
После основного прохода выполняется компенсационный проход по неделям для недопоставленных пар. Ход решения
передаётся в интерфейс по неделям («Неделя 5 из 23: поставлено 1240 из 6962 пар»).

**Крупные задачи** (расписание всех групп организации): если переменных «поток × слот × аудитория» в недельной
модели больше порога (`SOLVER_ROOM_VARIABLES_LIMIT`, по умолчанию 60 000), аудитории в модель не входят. Решатель
выбирает слоты занятий с ограничением вместимости аудиторного фонда — для каждого набора подходящих аудиторий S число
занятий в слоте, которым подходят только аудитории из S, не больше |S| (условие Холла), — а конкретные аудитории
назначаются после решения паросочетанием (увеличивающие цепи; порядок — предпочтительная аудитория, затем
подходящая по размеру). Память решателя на задаче из 40 групп снижается с 2,5 до 0,5 ГБ.

**Режим «автоматически» и «CP-SAT»**: сначала за секунды строится эвристическое решение; оно передаётся CP-SAT как
стартовое (подсказки `hints`). Если на неделю CP-SAT не нашёл решение за отведённое время (большая организация и
маленький лимит), для этой недели ставятся подсказки, не противоречащие уже поставленному, — недели не остаются
пустыми; после исчерпания лимита оставшиеся недели тоже берутся из подсказок. Результат CP-SAT проходит доводку
(см. ниже), и в итог попадает лучший из трёх вариантов — «CP-SAT с доводкой», «CP-SAT», «эвристика» — по числу
поставленных пар, затем по окнам, поздним парам и перегруженным дням. Выбор и сравнение записываются в журнал.

Замер на базе филиала (40 групп СПО и ВО, 20 учебных планов, 8858 пар, лимит 300 с):

| Вариант | Пар | Окна у групп | Окна у преподавателей | Перегруженные дни |
| --- | --- | --- | --- | --- |
| Эвристика без доводки | 8796 | 42 | 203 | 98 |
| Эвристика с доводкой | 8796 | 9 | 116 | 90 |
| CP-SAT с доводкой (выбран) | 8797 | 4 | 94 | 83 |

С лимитом 60 с CP-SAT раньше не успевал решить ни одной недели и в режиме «CP-SAT» возвращал пустой результат;
теперь недели заполняются подсказками, а итог не хуже эвристики.

## Эвристический генератор

Используется как стартовое решение и запасной вариант в режиме «автоматически», при недоступности CP-SAT или по
выбору пользователя:

1. недели обрабатываются по порядку с той же накопительной целью;
2. пары ставятся жадно по принципу «самый ограниченный — первым» (меньше всего допустимых слотов);
3. для каждой пары перебираются допустимые слоты (дата × пара × аудитория), проверяются жёсткие ограничения,
   выбирается слот с минимальным штрафом;
4. если слота нет — ремонт (backtracking глубины 1): мешающее занятие переносится в другой допустимый слот;
5. финальные проходы компенсации: сначала с равномерным распределением, затем в любые свободные слоты;
6. **доводка окон** (режим «по датам», если включено «Убирать окна»): занятие переставляется на другую пару того же
   дня или на другой день той же недели, если это уменьшает окна групп и преподавателя, перегрузку дня и разрывы
   одной дисциплины с учётом поздних пар и пожеланий преподавателя. Все жёсткие ограничения проверяются заново;
   неделя занятия не меняется, поэтому темп и недельные лимиты сохраняются. Время доводки — до четверти лимита
   (не более 30 с).

Эта же процедура дорабатывает готовое решение CP-SAT (`initial`): его занятия переносятся с проверкой ограничений,
недопоставленные пары досаживаются компенсационными проходами, затем выполняется доводка окон.

**Поздние пары** считаются нарушением только у групп без особого режима: если режим занятий группы сам включает
поздние пары (вечерние и очно-заочные группы), они не учитываются ни в статистике, ни при выборе варианта.

## Результат и диагностика

Результат — предпросмотр в задании генерации: список занятий, статистика (требуется / поставлено пар и часов,
по группам, время расчёта, недели, нарушения мягких ограничений), предупреждения и **неразмещённые занятия**.

Для каждого неразмещённого потока диагностика последовательно сужает варианты («воронка») и указывает первую
причину, на которой их не хватает, с рекомендацией:

| Код | Причина | Рекомендация |
| --- | --- | --- |
| `NO_TEACHER` | Не назначен преподаватель | Назначить в «Нагрузке» |
| `NO_SUITABLE_ROOM` | Нет аудиторий подходящего типа и вместимости | Добавить аудитории или разрешить другой тип |
| `NO_PRACTICE_PERIOD` | Нет периода практики в графике | Добавить период практики |
| `NO_AVAILABLE_DAYS` | Нет учебных дней в интервале | Изменить период или график |
| `TEACHER_UNAVAILABLE` | Преподаватель недоступен в свободные слоты группы | Изменить доступность или преподавателя |
| `TEACHER_LEVEL` | Образование преподавателя не позволяет вести у группы этого уровня | Назначить преподавателя с подходящим образованием, степенью или званием |
| `TEACHER_NOT_EMPLOYED` | Преподаватель не работает в эти даты | Назначить другого или передать нагрузку с даты начала работы |
| `TEACHER_BUSY` / `TEACHER_LIMIT` | Преподаватель занят или достиг лимита | Другой преподаватель, увеличить лимит |
| `GROUP_BUSY` | Слоты группы заняты | Разрешить дополнительную пару или другой день |
| `ROOM_SHORTAGE` | Не хватает аудиторий в свободные слоты | Освободить или добавить аудитории |
| `DAILY_LIMITS` | Мешают лимиты дисциплины в день, окна, поздние пары | Ослабить ограничения |
| `NOT_ENOUGH_TIME` | Недостаточно учебного времени | Увеличить период или лимит времени |

Частичный результат можно применить: занятия ставятся, неразмещённые часы видны в контроле часов как дефицит.

## Применение результата

В одной транзакции удаляются заменяемые занятия периода (только незакреплённые, неручные, непроведённые, в статусе
«запланировано» и в интервале генерации) и создаются новые. Если после генерации кто-то вручную занял слот,
конфликтующие занятия пропускаются и перечисляются в ответе. Затем выполняется полная проверка периода; для
опубликованного расписания отправляются уведомления.
