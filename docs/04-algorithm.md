# 4. Алгоритм генерации расписания

Код: `apps/backend/src/scheduler` (построение задачи, эвристика, диагностика, задания) и `apps/solver/app` (CP-SAT).
Контракт задачи и результата общий для обоих решателей (JSON, `solver.types.ts` ↔ `models.py`).

## Режимы

| Режим | Когда использовать | Как работает |
| --- | --- | --- |
| Календарный (по датам) — рекомендуется | Семестр с праздниками, практиками, сессией, неравномерными неделями | Каждое занятие ставится на конкретную дату; учитываются все блокировки графика |
| Постоянная неделя | Стабильное расписание «по неделям» | Строится шаблон недели (пар в неделю ≈ часы / число учебных недель), затем разворачивается по датам с пропуском заблокированных дней; остаток часов добирается компенсационным проходом |

Практика в колледже и консультации всегда ставятся по датам (в периоды практики и перед окончанием семестра).

## Подготовка задачи

1. **Горизонт**: даты периода (или выбранный интервал) ∩ даты семестра, только рабочие дни недели.
2. **Календарь группы** (`CalendarContext`): для каждой даты — разрешены ли обычные занятия, идёт ли практика,
   какие события блокируют (каникулы, сессия, праздники, ГИА, практики на предприятии).
3. **Спрос**: потоки часов (см. [расчёт часов](03-hours.md)) → требуемое число пар с учётом уже существующих
   занятий: закреплённых, ручных, проведённых и находящихся вне интервала генерации. Неполная пара — отдельное
   требование с `academicHours = 1`.
4. **Допустимые аудитории** для каждого потока: тип аудитории (из плана или назначения), вместимость ≥ размер группы
   или подгруппы, доступность; предпочтительная аудитория получает бонус.
5. **Преподаватели**: недоступные слоты (жёстко), предпочтения (веса), лимиты пар в день и неделю, периоды
   отсутствия из графика.
6. **Фиксированные занятия** занимают слоты групп, преподавателей и аудиторий и не изменяются.

## Темп распределения

Чтобы часы шли равномерно, а не «в начале семестра», для каждого потока считается накопительная цель к концу
недели:

```
цель(w) = min(требуется, round(max(требуется × дней_до_конца_w / всего_дней,  интенсивность × недель_до_w)))
```

где «дни» — учебные дни группы, а интенсивность — `weeklyLessonTarget` назначения (если задана). В неделю ставится
`цель(w) − уже поставлено`; отставание компенсируется в следующих неделях.

## OR-Tools CP-SAT (основной решатель)

Модель строится по неделям (скользящий горизонт): булевы переменные `x[поток, день, пара, аудитория]` только для
допустимых сочетаний.

Жёсткие ограничения:

- группа (вся или подгруппа) — не более одного занятия в слоте; занятие всей группы исключает подгрупповые в этом слоте;
- преподаватель — не более одного занятия в слоте (общий поток групп — одно занятие);
- аудитория — не более одного занятия в слоте, тип и вместимость подходят;
- доступность преподавателя и аудитории, календарные блокировки (разрешённые даты);
- лимиты преподавателя в день и неделю, не более N пар одной дисциплины в день, сетка звонков (пар в день);
- число поставленных пар потока за неделю не превышает недельной потребности.

Мягкие ограничения (штрафы, веса настраиваются в «Настройках»):

| Штраф | Вес по умолчанию |
| --- | --- |
| Окна у групп | 30 |
| Превышение комфортного числа пар группы в день | 25 |
| Переходы между корпусами | 15 |
| Окна у преподавателей | 10 |
| Неравномерность по неделям | 10 |
| Поздние пары | 8 |
| Нарушение пожеланий преподавателя | 6 |
| Сложные дисциплины в конце дня | 6 |
| Превышение частоты дисциплины в неделю | 5 |
| Повтор дисциплины в один день | 3 |

Цель: максимум поставленных пар (с учётом приоритета потока) минус штрафы. Лимит времени делится между неделями.
После основного прохода выполняется компенсационный проход по неделям для недопоставленных пар.

## Эвристический генератор (резерв)

Используется при недоступности CP-SAT или по выбору пользователя:

1. недели обрабатываются по порядку с той же накопительной целью;
2. пары ставятся жадно по принципу «самый ограниченный — первым» (меньше всего допустимых слотов);
3. для каждой пары перебираются допустимые слоты (дата × пара × аудитория), проверяются жёсткие ограничения,
   выбирается слот с минимальным штрафом;
4. если слота нет — ремонт (backtracking глубины 1): мешающее занятие переносится в другой допустимый слот;
5. финальные проходы компенсации: сначала с равномерным распределением, затем в любые свободные слоты.

## Результат и диагностика

Результат — предпросмотр в задании генерации: список занятий, статистика (требуется / поставлено пар и часов,
по группам, время расчёта, недели, нарушения мягких ограничений), предупреждения и **неразмещённые занятия**.

Для каждого неразмещённого потока диагностика последовательно сужает варианты («воронка») и указывает первую
причину, на которой их не хватает, с рекомендацией:

| Код | Причина | Рекомендация |
| --- | --- | --- |
| `NO_TEACHER` | Не назначен преподаватель | Назначить в «Нагрузке» |
| `NO_SUITABLE_ROOM` | Нет аудиторий подходящего типа и вместимости | Добавить аудитории или разрешить другой тип |
| `NO_PRACTICE_PERIOD` | Нет периода практики в графике | Добавить период практики |
| `NO_AVAILABLE_DAYS` | Нет учебных дней в интервале | Изменить период или график |
| `TEACHER_UNAVAILABLE` | Преподаватель недоступен в свободные слоты группы | Изменить доступность или преподавателя |
| `TEACHER_BUSY` / `TEACHER_LIMIT` | Преподаватель занят или достиг лимита | Другой преподаватель, увеличить лимит |
| `GROUP_BUSY` | Слоты группы заняты | Разрешить дополнительную пару или другой день |
| `ROOM_SHORTAGE` | Не хватает аудиторий в свободные слоты | Освободить или добавить аудитории |
| `DAILY_LIMITS` | Мешают лимиты дисциплины в день, окна, поздние пары | Ослабить ограничения |
| `NOT_ENOUGH_TIME` | Недостаточно учебного времени | Увеличить период или лимит времени |

Частичный результат можно применить: занятия ставятся, неразмещённые часы видны в контроле часов как дефицит.

## Применение результата

В одной транзакции удаляются заменяемые занятия периода (только незакреплённые, неручные, непроведённые, в статусе
«запланировано» и в интервале генерации) и создаются новые. Если после генерации кто-то вручную занял слот,
конфликтующие занятия пропускаются и перечисляются в ответе. Затем выполняется полная проверка периода; для
опубликованного расписания отправляются уведомления.
